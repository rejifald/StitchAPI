The authoring surface: the exports that produce a stitch. For what goes inside
the config object, see [Reference → Config types](/docs/reference/config-types).

## stitch()

`stitch<T>(config)` takes a path string or a partial config and returns a
`Stitch<T>`. Compose shared configuration via the `extends` key.

```ts twoslash
import { stitch } from 'stitchapi';

const user = stitch<{ id: string }>({
    path: 'https://api.example.com/me',
});
```

## graphql()

`graphql<T>(config)` is a thin wrapper over `stitch()` for GraphQL-over-HTTP: it POSTs
`{ query, variables }` and picks `data`. The config must carry a `document`.

```ts twoslash
import { graphql } from 'stitchapi';

const viewer = graphql<{ viewer: { id: string } }>({
    path: 'https://api.example.com/graphql',
    document: 'query { viewer { id } }',
});
```

See [Guide → graphql](/docs/guides/data/graphql) for usage.
